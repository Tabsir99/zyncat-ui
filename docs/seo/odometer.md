# odometer - keyword research

Primary: number counter animation (KD 0, >100, ranks for: lottiefiles #1 / 150 mo, framer #2, videocaptions #3, commoninja #5, krumzi #7)
Secondary: animated number counter, counter animation, react odometer, count up animation

## The finding that shaped the page

Five different pages earn traffic from `number counter animation` and not one of them
ships code: a Lottie file, a Framer marketplace tag, an AI video-caption motion element,
a Common Ninja embed widget and a GIF generator. The only code results in the cluster
(`reactbits.dev/text-animations/count-up` #5/#6, `animate-ui.com/.../counting-number` #8)
sit below all of them. A React docs page that answers the effect query with a real
component, and says out loud that it is not a GIF, has an open lane.

The incumbents split cleanly by name, not by subject:

| Page                                           | Traffic | Owns                                            |

| `inorganik.github.io/countUp.js/`              | 4.5K/mo | `countup js` #1 (1.4K), `count up` #2 (400)     |

Two conclusions come straight out of that table. `number ticker` is Magic UI's coined
term with no independent demand behind it (their page earns 16/mo and Ahrefs lists no
keywords for it at all), so it belongs in `keywords`, not the title. And the whole
generic cluster - `number counter animation`, `animated number counter`, `counter
animation`, `count up animation`, `number animation`, `animated numbers` - comes back
**KD 0-1**. Difficulty is not what is holding this page back; nothing is.

## Does "odometer" survive in the title? Yes - never bare, never first.

Bare `odometer` is >10K volume, KD Hard, and 100% automotive: the generator returned
`odometer reading`, `odometer disclosure statement`, `odometer fraud`, `odometer
rollback`, `bike odometer`, `michigan odometer statement`, and 20 questions of which
every single one is a car or DMV question (`how to reset odometer`, `how to change
mileage on a digital odometer`). We cannot win that SERP and would not want the clicks.

But the _modified_ term is a different keyword with a different SERP. `react odometer`,
`odometer animation`, `odometer effect`, `odometer css` all return KD `null` - no
competition measured at all - and `odometer js` is KD 19 with the #1 result being
HubSpot's 2013 library earning 20 visits a month. Nobody searching `react odometer`
wants mileage.

So the word stays, under two rules that the title obeys:

1. **Never first.** `React` leads, which forecloses the automotive reading before the
   crawler or the human reaches "Odometer".
2. **Never bare.** It is bracketed by `React` on one side and `Number Counter
Animation` on the other, so every neighbouring token confirms the effect sense.

`React Odometer Number Counter Animation` (39 chars) keeps the primary phrase contiguous,
picks up `react odometer` free, and matches the page's H1, which is the word `Odometer`.
Rejected alternatives: `Odometer Number Counter Animation` (leads bare - mileage risk),
`React Number Counter Animation` (drops a free zero-competition cluster and mismatches
the H1), `React Number Ticker & Odometer` (`number ticker` has no proven demand).

No mileage vocabulary appears in the title, description, keywords, lede or FAQ.

## Notes on what the FAQ may claim

Every FAQ answer is grounded in `src/components/expressive/odometer/Odometer.tsx`,
`odometer.css`, `src/engine/loop.ts` or `README.md`:

- `value`, `format`, `speed`, `className`, `style`, `htmlProps` are the whole prop surface.
  There is no scroll-trigger prop, no duration prop and no decimals prop, so the scroll FAQ
  says so rather than inventing one.
- `format={(v) => v.toLocaleString('en-US')}` and `format={(v) => String(v).padStart(8, '0')}`
  are the two presets in the docs playground - both are real, both are quoted verbatim.
- Non-digit characters becoming static separators is `/\d/.test(char)` in the render.
- "Absorbed rather than restarted" is `aimColumns`, which re-aims `target` while leaving
  `position` and `velocity` untouched.
- "Columns always roll forward" is `while (target < column.position + ARRIVAL_MARGIN)
target += DIGITS_PER_RUN` - the target is advanced until it is ahead, so a decreasing
  value still rolls forward, exactly like the mechanical instrument.
- Motion blur and accent tint are `--_odometer-blur` and `--_odometer-velocity`, written from
  `Math.abs(column.velocity)` each frame.
- Off-screen and hidden-tab pausing is `loop`'s `IntersectionObserver` plus the
  `visibilitychange` listener; `Odometer` passes `el`, so both apply.
- Reduced motion is `UIMotion.reduced` in both `Odometer` and `loop`: `snapColumns` runs and
  the loop never starts.
- SSR: the formatted string is server-rendered inside `.zc-odometer__label`, which is visually
  hidden but present in the HTML; the digit columns are `aria-hidden` and are positioned by
  JS after hydration. The FAQ is worded to match that exactly.
- React 19, compiled ESM with `'use client'` intact, no `transpilePackages`, zero runtime
  dependencies: `README.md`.
